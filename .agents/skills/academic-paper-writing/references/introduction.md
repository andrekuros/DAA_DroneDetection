# Introduction

## Goal

Motivate the gap, define the fair baseline, and list testable contributions. End so Methods feels necessary, not optional.

## Mini-outline

1. Opening: application + why allocation matters
2. Standard regime where classical solvers are strong
3. Challenge regime (incomplete info, windows, etc.) with citations
4. Fair baseline + oracle (what Global means)
5. This paper’s approach in one crisp paragraph
6. Numbered contributions (testable)
7. Optional roadmap sentence

## Paragraph roles

- **opening** — domain stakes, no hype
- **challenge** — assumptions that break
- **baseline** — Local vs Global / fair competitor
- **method** — approach class
- **advantage** — what is new *and checkable*
- **evidence preview** — only if abstract-level result is locked

## Contribution bullets

Each bullet must be falsifiable (metric, suite, comparison). Separate positive claims from honest negatives.

## Avoid

Inflated motivation; undefined jargon; contribution lists that restate Methods headings; claiming architecture wins without matched controls.
