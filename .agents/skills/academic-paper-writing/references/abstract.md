# Abstract

## Goal

One dense paragraph that a busy reviewer can trust: problem, approach class, primary result with protocol, and scope.

## Mini-outline (before prose)

- Problem / setting (1 clause)
- Method class (not full architecture dump)
- Primary quantitative finding + statistical protocol
- Non-claims / scope (sim-only, suite, what is *not* shown)

## Paragraph rules

Usually **one** paragraph (two only if venue allows extended abstracts).
- First sentence: problem + why standard solvers struggle (or the gap).
- Middle: what you do (hybrid / architecture / protocol) without equation spam.
- End: main number or qualitative result with N/CI language; explicit limit.

## Must / avoid

| Must | Avoid |
|------|--------|
| Match table numbers exactly | “Novel / first / powerful” |
| Name fair baseline | Listing every ablation |
| State evaluation protocol briefly | Promising future work |

## Claim–evidence

Every quantitative phrase in the abstract must map to a table/figure. If dual thesis, both claims appear; neither is buried.
